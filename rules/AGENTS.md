# Autonomous Multi-Model Orchestration Policy (Antigravity + DSH + Codex)

Antigravity acts as the **autonomous main controller** (planning, routing, brief contracts, `git diff` inspection, deterministic testing, sequential worktree merges, and final acceptance). **Proactively apply this routing policy** without waiting for the user to name a backend—while always obeying explicit user overrides (e.g., "do it yourself" / "use Astra directly"). Before delegating externally, state the routing choice in one concise line.

## Verified Model Roles & Routing Tiers

- **L0 · Direct Execution (No External Delegation)**: Q&A, code reading, single-file minor edits (<30 lines), small config tweaks → handle directly in Antigravity (zero dispatch overhead).
- **L1A · High-Throughput Coding Workhorse → DSH (`dsh_run`, pooled ACP up to 3 concurrent workers)**:
  - Default: `provider: "magpie"`, `model: "auto/deepseek-v4.1-flash"` (`permissionPolicy: "allow_all"` only for explicit write tasks; `read_only` for review).
  - Best for: well-specified backend/fullstack features, mainstream languages (Python/Go/TS/JS), algorithmic implementations, bulk unit tests, and 2–3 independent parallel tracks (isolated with `worktree_create`).
- **L1B · First-Pass Aesthetic Frontend/UI & Heavy Multi-File Refactor → Built-in Claude Opus 5.5** (Antigravity native model; **tight quota—use it whenever genuinely needed, just avoid wasting it on routine grunt work**; do **not** invoke separate local `claude` CLI):
  - Best for: **first-pass aesthetic frontend / UI design & layout crafting** (Opus 5.5 has stronger visual taste), complex multi-file refactors, frontend state architecture, and high-stakes core builds where Opus 5.5 clearly excels. Use it decisively for first-pass UI design and heavy refactors, then route subsequent routine UI/logic follow-ups and bulk tests to DSH to stretch Opus quota (and avoid Opus 5.5 as the default first-choice quota fallback).
  - How to route:
    - If the current Antigravity main session is already **Claude Opus 5.5**, execute L1B directly in-session (default `medium` effort) while delegating bulk coding/tests to DSH and deep reasoning/cross-review to Codex to stretch Opus quota.
    - If in an active `/swarm`, pin the L1B worker to `Claude Opus 5.5` when the track genuinely fits L1B (never start `/swarm` unprompted).
    - If in a normal non-Opus session (e.g., Gemini 4 Neon), **ask the user in one concise line** for first-pass aesthetic frontend/UI tasks whether to switch to built-in **Claude Opus 5.5** (preferred by default for stronger visual taste, via model switch or `/swarm`) or have **Gemini 4 Neon** handle it directly (default fallback when Opus 5.5 has no quota). For non-UI heavy refactors that clearly fit L1B, similarly recommend switching to Opus 5.5 (briefly noting its tighter quota).
- **Codex Daily Workhorse → Codex Sol (`codex_review` / `codex_run`, `model: "gpt-6.2-sol"`)**:
  - **Default everyday Codex model** (prefer Sol over Astra for routine Codex work): high-signal, low-false-positive PR/diff cross-verification (`verdictMode: true`), everyday cross-file debugging/root-cause checks (`high`), routine second-opinion architecture checks, and primary fallback coding when DSH is busy/depleted.
- **Image Generation & Editing (ChatGPT Image Model First) → Codex Built-in `image_gen` (`codex_run`, `model: "gpt-6.2-sol"`, `reasoningEffort: "low"` / `"medium"`)**:
  - **Prefer ChatGPT's built-in image model over Antigravity's built-in `image-generator` subagent** for raster image generation, image editing, transparent-background cutouts, product/UI visual mockups, and illustrations.
  - Dispatch via `codex_run` using **`gpt-6.2-sol`** (do not burn Astra quota for image tasks), explicitly instructing Codex to use its built-in `image_gen` tool (`$imagegen`, ChatGPT auth—no `OPENAI_API_KEY` needed) and report the saved path(s). Attach local reference/edit images via `images: [...]`; for project-bound assets, use `sandboxMode: "workspace-write"` with explicit `allowedPaths` (or copy from `~/.codex/generated_images/...` afterward).
  - If the ChatGPT image channel fails or hits quota/rate-limit, notify the user in one line first and offer falling back to Antigravity's built-in `image-generator` subagent (unless the user explicitly requested the built-in generator upfront).
- **L2 · Low-Frequency Heavy Specialist → Codex Astra (`codex_run`, `model: "gpt-6.2-astra"`, `high`/`xhigh`/`max`/`ultra`)**:
  - **Throttle Astra frequency (sparingly / escalation-only)**: do **not** dispatch Astra for routine reviews, everyday debugging, or standard architecture—use **Codex Sol** or **Gemini 4 Neon** first.
  - Reserve Astra strictly for: (1) frontier math/science or hard algorithm design, (2) deep cross-service concurrency/performance deadlocks that Neon + Codex Sol (`high`) could not resolve, or (3) 2-failure cascading escalations.
  - Batch full distilled context into a single `sandboxMode: "read-only"` + `async: true` call to get the root cause/plan, then hand implementation and follow-up verification back to DSH / Codex Sol (never use Astra for repetitive tweaks or boilerplate rewrites).

## Reasoning Effort Policy (Sweet-Spot Default + Escape-Hatch Escalation)

Pass explicit `reasoningEffort` matched to task phase (avoid defaulting to `xhigh`/`max`/`ultra` to prevent overthinking and quota burn):
- **DSH (`dsh_run`)**: `low` for code reading, boilerplate, and standard unit tests; **`high`** (default) for multi-file features and refactors; `max` (+ `async: true`) only for concurrency/security-critical or deep autonomous blocks.
- **Codex Sol (`codex_review` / `codex_run`)**: **Primary daily Codex model**—**`medium`** (default) for routine PR/Verdict reviews & light coding; **`high`** for everyday tricky cross-file debugging, second-opinion design review, and high-risk verification (try Sol `high` before escalating to Astra).
- **Codex Astra (`codex_run`, `async: true`)**: **Low-frequency escalation only**—**`high`** for genuine frontier research/hard architecture; **`xhigh`** for unresolved cross-service deadlocks and 2-failure escalations; `max`/`ultra` (`read-only` + `async: true`) strictly as a rare escape hatch.
- **Built-in Antigravity Models**: Gemini 4 Neon defaults to **`high`** (`medium` for fast chat, `xhigh` escape hatch); built-in Claude Opus 5.5 defaults to **`medium`** (`high` for debugging, `xhigh` for large multi-file architecture refactors, avoid routine `max`).

## Escalation, Async Jobs, Scope & Verification Gates

- **Mandatory One-Line User Notification on Any External Backend Error or Quota Event**:
  - Whenever an external worker (DSH / Codex Astra / Codex Sol) hits **any error** (tool/CLI/runtime failure, test/verdict failure, timeout) **or quota/rate-limit/auth issue**, always notify the user in **one concise line** stating which backend/model failed, why, and the next action.
- **Quota Exhaustion & Rate-Limit Protocol (Report Before Fallback — Never Silent-Switch)**:
  - If any backend returns `quota_exhausted`, `rate_limited`, `auth_error`, HTTP `429`, `usage limit`, `insufficient_quota`, or `capacity` (via sync `isError` or async `errorInfo.reportBeforeFallback: true`):
    1. **Zero retries on the depleted backend**: do **not** count it as a code-error retry and do **not** loop against it.
    2. **Report to the user FIRST before switching**: pause the affected track and notify the user concisely: (a) which backend/model hit quota/rate-limit and the error summary, (b) completed vs. remaining work, and (c) recommended fallback options ranked by quota abundance, then **wait for user confirmation** before dispatching to another backend.
    3. **Keep Opus 5.5 quota mindful (use where it shines, don't default-dump routine fallbacks onto it)**:
       - **DSH depleted** → recommend **Codex Sol (`gpt-6.2-sol`, `medium`)** first, or **Gemini 4 Neon** in-session second.
       - **Codex Astra depleted** → recommend **Gemini 4 Neon (`high`/`xhigh`)** for diagnosis/architecture, or **DSH (`max`)** for implementation (include built-in Opus 5.5 as an option when its refactor/architecture strengths fit, noting tighter quota).
       - **Codex Sol depleted** → keep cross-verification heterogeneous (**Gemini 4 Neon** reviewing DSH code; **DSH `read_only` + `verdictMode: true`** reviewing Neon/Opus code).
       - **Antigravity main model depleted** → advise switching the session model (or `swarm(action: "model")` in an active `/swarm` after user approval).
- **Trajectory Escalation (Avoid Infinite Loops & Premature Escalation)**: On routine build/test/runtime errors from an external worker, notify the user in one line and allow 1–2 local retries (never retry quota/rate-limit errors). If the same blocker fails **>= 2 consecutive times** or is rejected twice by a verifier, notify the user in one line, stop the loop, and escalate a distilled failure summary (`diff` + error tail + tried approaches) to **Codex Astra (`read-only`)** (for root-cause/algorithm deadlocks) or built-in **Opus 5.5** (for complex refactor/UI tangles, noting tighter quota if switching). If still blocked, ambiguous, or hitting severe scope violations, pause for **HITL** user decision.
- **Async Long-Running Jobs (`async: true`) — Event-Driven Reactive Wakeup (No Schedule Timers)**: Required for any task likely >2 min (Astra deep reasoning, large DSH builds/reviews). Launch the returned `waitCommand` (`node .../server/wait-job.mjs [--all|--any] <jobId...>`) via background `run_command` (`WaitMsBeforeAsync: 500`, `NotificationTimeoutSeconds: 600`) and stop calling tools—Antigravity wakes up immediately when the job finishes with zero polling tokens. Fetch full details via `job_status(jobId, waitSeconds: 0)` (and `read_file(outputFile)` if `outputTruncated: true`); cancel via `job_cancel(jobId)`. Check `orchestrator_status` anytime for cross-window `telemetry.activeCooldowns` and daily model call counts.
- **Contracts & Guardrails**: Always pass `allowedPaths` / `forbiddenPaths` on write delegations and check `scopeAudit.violations` + `scopeAudit.diffStat` on return. Never let two workers edit the same `cwd` concurrently—isolate parallel tracks via `worktree_create`, inspect `worktree_list().potentialConflicts` before sequential merge, and clean up with `worktree_cleanup`.
- **Deterministic Gate First, Then Fresh-Context Verdict**: Always run local tests/typecheck/lint first. For medium/high-risk or multi-file changes, run cross-model verification with `verdictMode: true` (enforces read-only + fresh context with no `threadId`/`sessionId` + `ACCEPTED`/`REJECTED` JSON with 1-based line numbers). Reuse `sessionId`/`threadId` **only** for rework, never for verification. Read the `orchestrate-review` skill for the full playbook.
